## Global Constraints

- Retain application ID/namespace `com.example.acetimetracker`, `minSdk 27`, `compileSdk 37` and P1's final `targetSdk 36`.
- Preserve existing Firebase accounts, email/password registration/sign-in/reset and existing profile URLs. Keep production Firebase client configuration unchanged.
- `users/{uid}` contains profile fields and legacy `dailyTimesheetEntries`, `minGoal`, `maxGoal` and possibly unknown fields. Profile bootstrap and editing must preserve unrelated data; P2 must not mark canonical migration complete.
- Existing `email` is the profile's contact/display email. FirebaseAuth is authoritative for sign-in email. Name/photo/contact edits never update sign-in credentials.
- Empty UID fails before constructing document or Storage paths. Operations capture their originating UID/session generation and reject stale callbacks after sign-out/account replacement.
- Use the existing XML controls with bounded correctness/loading/error changes. Compose navigation/design tokens, DataStore preferences, canonical goals/sessions, Room/outbox, durable timer checkpoints and reminders remain P3–P10 work.
- Keep the existing `app_settings` preference keys `theme` and `notifications`. Do not implement guest accounts, social login or new account deletion flows.
- All automated account/data tests use the isolated demo project. No production service writes, rules deployment, PR merge, publication or iOS work.

## Review Focus

1. Auth may succeed before profile setup fails: retry profile setup under that UID, without repeating account creation. Task 1 owns the test.
2. Registration's auth listener can fire before its create-user task returns: bind the submitted name to the returned UID before profile initialization; never give it to another account. Task 1 owns the test.
3. A late callback from account A may arrive while account B is active: it cannot route, render or start a write using B. Both tasks own stale-result tests.
4. Existing root data and missing/malformed profile fields must survive bootstrap/edit; two devices may bootstrap concurrently. Task 1 owns preservation/concurrency tests; Task 2 owns patch tests.
5. Photo upload, download-URL lookup, profile acknowledgement and email verification are distinct outcomes. Task 2 owns failure/retry/recreation tests and truthful UI state.

Pending authentication also has its own attempt generation. A late sign-in/create-user SDK success after explicit sign-out must not reestablish an abandoned session; existing UID/token checks alone cannot prove that. Task 1 owns this regression and startup reconciliation.

## Shared contracts and file responsibilities

Types belong in `app/src/main/java/com/example/acetimetracker/core/model/AccountModels.kt`:

- `AuthIdentity(uid: String, signInEmail: String?, emailVerified: Boolean, displayName: String?)`.
- `AuthState`: `Restoring`, `SignedOut`, `SignedIn(identity: AuthIdentity)`.
- `SessionToken(uid: String, generation: Long)`. Generation changes on sign-out/account replacement, including signing back into the same UID. An ordinary identity refresh for the same session retains it.
- `UserProfile(uid: String, displayName: String?, contactEmail: String?, photoUrl: String?)`. Safe reads tolerate absent/non-string legacy profile values without overwriting them.
- `SessionState`: `Restoring`, `SignedOut`, `LoadingProfile(token, identity)`, `ProfileError(token, identity, message)`, `Ready(token, identity, profile)`; the named parameters use the types above and `message: String`.

`core/data/account/AuthRepository.kt` produces `val state: StateFlow<AuthState>`, `fun currentUid(): String?`, `suspend fun register(email: String, password: String): AuthIdentity`, `suspend fun signIn(email: String, password: String): AuthIdentity`, `suspend fun sendPasswordReset(email: String): Unit`, and `fun signOut(): Unit`. `FirebaseAuthRepository.kt` implements it with Firebase callbacks/tasks. `currentUid()` reads the SDK's current identity so a queued listener cannot validate a stale token.

`core/data/profile/ProfileRepository.kt` produces `suspend fun bootstrap(token: SessionToken, identity: AuthIdentity, registrationName: String?): UserProfile` and `fun observe(token: SessionToken): Flow<UserProfile>`. `FirebaseProfileRepository.kt` owns Firestore paths and transactions. Bootstrap adds only absent profile keys for which an actual value is available: registration name, otherwise Auth display name; Auth email for missing contact `email`. Never fill an unknown name with invented identity. Existing explicit null/blank values and unknown fields remain unchanged. No photo is required.

`app/SessionGuard.kt` owns token validity independently of UI state: `class SessionGuard(currentUid: () -> String?)` produces `fun bind(uid: String): SessionToken`, `fun invalidate(): Unit`, `fun currentToken(): SessionToken?` and `fun isCurrent(token: SessionToken): Boolean`. Bind requires a nonblank UID matching the SDK; it reuses the token for the same active identity, otherwise increments generation. Invalidate clears the token and advances generation. The container constructs SDK instances, this guard, then adapters and the coordinator; all use the same guard, avoiding a repository/coordinator dependency cycle.

`app/SessionCoordinator.kt` produces `val state: StateFlow<SessionState>`, `fun currentToken(): SessionToken?`, `fun isCurrent(token: SessionToken): Boolean`, `suspend fun register(displayName: String, email: String, password: String): Unit`, `suspend fun signIn(email: String, password: String): Unit`, `suspend fun retryProfileBootstrap(): Unit`, and `fun signOut(): Unit`. Token methods delegate to SessionGuard. It serializes credential mutations and defers registration profile setup until the create-user result binds the submitted name to its UID. Restored sessions use the initial AuthStateListener result. Invalidate a session before SDK sign-out; cancel old profile observation and reject results whose token no longer matches the SDK UID/generation.

`app/AuthAttemptRegistry.kt` produces `fun begin(): Long`, `fun invalidate(): Unit` and `fun isCurrent(attempt: Long): Boolean`, independently of session tokens. The coordinator owns SDK credential operations in its application scope and serializes them until their underlying Tasks are terminal, even if a UI waiter cancels. During an attempt, buffer auth listener events until its result is reconciled. Sign-out invalidates the attempt immediately. A late abandoned success triggers SDK sign-out before another credential mutation starts; do not bootstrap, navigate or publish Ready from it. Reject listener payloads that no longer match the SDK's current UID.

`app/PendingAuthCancellationStore.kt` produces `fun markAbandoned(): Unit`, `fun needsReconciliation(): Boolean` and `fun clear(): Unit`, storing only a cancellation marker in private `account_session` preferences, never credentials or a replacement login boolean. Persist the marker before sign-out abandons an unresolved SDK credential operation. At startup reconcile that marker by clearing any SDK user before accepting restoration; remove it only after reconciliation. Normal restoration still comes from Firebase Auth. This closes the process-recreation window between a late SDK success and cleanup; it does not implement P4's tracking outbox.

`app/AppContainer.kt` constructs these adapters/coordinator and ViewModel factories without adding a DI framework. `app/AceTimeTrackerApplication.kt` owns the application scope/container and Firebase initialization. `app/SessionRouter.kt` produces `fun openSignedOut(activity: Activity): Unit` (Login) and `fun openReady(activity: Activity): Unit` (MainActivity), using `FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TASK` for account-boundary transitions. Login gains a `Create account` link to Registration; Registration retains its Login link. Guard navigation against repeated observations of the same destination/session.

`app/AccountActivity.kt` extends `LegacyActivity`, exposes `protected fun requireSessionOrRoute(): SessionToken?` and `protected fun isCurrentSession(token: SessionToken): Boolean`, and watches session invalidation while started. Every protected activity calls the first function immediately after `super.onCreate`, before inflation/data access, and returns if it yields null. A lost session clears sensitive views/listeners and routes through the session gate. Account-specific writes use the captured token UID; callbacks validate it before rendering or chaining another request.
